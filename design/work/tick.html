Design system · Case study

Tick

A design system for a crypto trading app where colour must mean the right thing in every market. I wrote the spec, AI drafted it, and I audited and fixed it.

RoleDesign systems
DateOct 2026
ToolsFigma, Figma AI, variables
ScopeTokens, components, templates

Key decisions

  1. Separate value from intent.Components ask for a meaning like “price down”; tokens pick the colour per mode.
  2. Market direction is its own mode.Green-up/Red-up flips price colours only. Success and error never change.
  3. A mono font for numbers.Equal-width digits keep prices lined up as they update.
  4. AI drafts, I audit the components.That’s where real bugs hide: wrong totals, crossed order-book data.

01 · The problem

In trading, colour means two things at once.

Apps use green for success and red for errors. Trading apps also use them for price up and down. And in markets like mainland China, red means up.

If one red token does both jobs, a normal price drop looks like an error, and switching to Red-up turns every error green. So one rule underpins everything:

Principle

Separate value from intent.

Components ask for a meaning, like “price down” or “error”, and the tokens pick the colour for the current mode.

02 · The spec

I wrote the spec before anything was generated.

Three token layers, two independent sets of modes, and the components and templates to support. The spec became the AI’s brief and my audit checklist.

Two independent switches. Light/Dark and Green-up/Red-up are stored separately: four valid combinations, and success and error never change.

03 · Foundations

Foundations: colour, space, shape and type.

Five colour ramps, a 4px spacing scale, six radii and ten type styles. Components only reach them through the semantic layer.

Numbers get their own font. Inter for text, Roboto Mono for prices, because equal-width digits keep columns aligned and stop prices jumping as they update.

04 · Core components

Core components, each with a contract.

Six core components: Button, Input, Tabs, Tag, Toast and Segmented control. Each documents its states, properties and usage rules, so designers and engineers decide the same way.

Button

Blue for actions. Green and red only for Buy and Sell. Loading keeps the same size and blocks double-submitting an order.

Input

Units like “BTC” sit outside the input, so they never shift as you type. Errors use the error colour, never “price down”.

Tag

“Filled” is always success, in Green-up and Red-up. Tags show status, never price movement.

05 · Templates

Templates prove the tokens work.

Trade and Wallet templates for desktop and mobile, each rendered in Light · Green-up and Dark · Red-up. If the tokens are wired right, only colours change, never layout or meaning.

06 · Explorations

Three directions I didn’t ship.

Three directions on the same tokens: glassmorphism, pastel “pop” and electric blue. None made the core library.

Why glass lost: blur behind prices changes contrast with whatever’s underneath, and numbers must be readable every time. Surfaces stay solid; glass is noted for lighter onboarding screens.

07 · The audit

AI did the first pass. I checked the parts that matter.

AI side note

Tool

Figma’s AI agent

Used for

Generating the first pass of tokens, components and templates from my spec.

Prompt

Summarised from my spec: “Build a design system for a crypto trading app: primitive, semantic and market tokens; Light/Dark and Green-up/Red-up modes; core and trading components like an order book and buy/sell panel; web and mobile templates.”

Figma’s AI agent generated the first version. I audited the components and token values, not the docs, because that’s what ships.

What I found: clipped button variants, wrong buy/sell totals, crossed order-book data, and a price-down colour that clashed with error red.

08 · The fixes

Every fix is logged with before and after.

Each fix is logged with before/after screenshots, so anyone can see what changed and why.

What I learned: AI makes a fast first draft, but checking the numbers and states is still my job.

09 · Trade-offs

The calls I made, and what they cost.

AI shifted my time from drawing to checking.

Decision

Who makes the first draft?

  1. ✓

    AI first pass, then my audit (chosen)

    Much faster to get every token and component on the page.

  2. ✕

    Build everything by hand (not chosen)

    Fewer surprises, but far slower, and I’d have spent my time on layout instead of correctness.

Decision

Where should the audit focus?

  1. ✓

    Components and token values (chosen)

    That’s what people build with. A wrong total on a buy/sell panel is a real bug.

  2. ✕

    The documentation pages (not chosen)

    They looked polished, but errors there don’t ship into products.

Decision

What colour means “price down”?

  1. ✓

    Its own token, separate from error red (chosen)

    Losing money isn’t an error. Mixing them makes a normal market move look like something broke.

  2. ✕

    Reuse the error red (not chosen)

    Fewer tokens, but the meaning gets muddy.

What worked

  • Green-up/Red-up as a mode, not hard-coded colours: one system for both conventions.
  • Before/after logs made the audit easy to review.

What I’d change

  • Write acceptance checks into the spec, so AI output can be tested against them.
  • I audited the main components; every variant is still to do.
